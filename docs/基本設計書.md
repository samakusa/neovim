# 基本設計書

## 概要
本リポジトリは、Neovimのエディタ設定一式（プラグイン管理、LSPによるコード補完・静的解析、シンタックスハイライト、IME自動制御、アウトライン表示、Markdown/HTMLプレビューなど）を管理し、`deploy.sh`によって実行環境（Windows / macOS / Linux）のNeovim設定ディレクトリへ配置するための設定リポジトリである。

## 用語の定義
| 用語 | 説明 |
| --- | --- |
| dein.vim | Neovim/Vim用のプラグインマネージャ。本リポジトリの全プラグインの追加・更新・管理に使用する。 |
| LSP（Language Server Protocol） | エディタと言語サーバー間で、コード補完・診断（エラー/警告表示）・定義ジャンプ等の機能をやり取りするための標準プロトコル。 |
| nvim-cmp | LSPやスニペット等、複数の補完ソースを統合してNeovim上で補完候補を表示するプラグイン。 |
| Treesitter（nvim-treesitter） | 構文木を解析してシンタックスハイライトを行うプラグイン。 |
| IME（Input Method Editor） | 日本語入力等、非ASCII文字を入力するための入力方式エディタ。 |
| ctags | ソースコード中の関数・見出し等の定義位置を索引化するツール。Vista.vimによるアウトライン表示の裏側で利用する。 |
| dein_plugin_root_dir | dein.vimがプラグイン本体を配置するディレクトリを指すグローバル変数。OSごとに異なるパスを`init.vim`で設定する。 |

## 機能
本リポジトリが提供する機能は以下の通り。

| # | 機能 | 概要 | 主な実装ファイル |
| --- | --- | --- | --- |
| 1 | 基本エディタ設定 | インデント幅、ステータスライン表示、クリップボード連携、検索挙動（デフォルトでハイライト検索OFF）、文字コード、OSごとの設定パス切り替えなど、Neovim全体の基本動作を定義する。行番号表示切り替え（`<C-n>`）、検索ハイライト切り替え（`<C-h>`）のキーマップも含む。また`vim.o.exrc = true`（`secure`は既定値のまま変更しない）を設定しており、開いたファイルのプロジェクトルート等に置かれたローカルの`.nvim.lua`/`.exrc`が、危険なコマンド実行が制限されたサンドボックス内で自動読み込みされる（`:h 'exrc'`, `:h 'secure'`）。これは主に機能4-2（Java/jdtls）のプロジェクトごとの設定上書きに利用する。 | `init.vim` |
| 2 | プラグイン管理 | dein.vimを用いて、Markdown/アウトライン/補完/シンタックスハイライト等の各種プラグインを一括管理し、未インストール時は自動インストールする。 | `load_dein.vim` |
| 3 | IME自動制御 | インサートモードを抜けた際に自動で英数入力モードへ切り替える。Windowsでは`zenhan`、macOS/Linuxでは`im-select`を利用し、OSごとに実装を切り替える。 | `load_ime_control.vim` |
| 4 | LSPによるコード補完・静的解析 | `nvim-cmp`と`nvim-lspconfig`を用い、Python（Ruff/Pyright）、Rust、TypeScript/JavaScript（ts_ls、ESLint）、C/C++、C#、Vim script、HTML/CSS/JSON、Lua、PowerShellなど多数の言語のLSPサーバーを一括セットアップする。コード定義ジャンプ、ホバー表示、リネーム、コードアクション、カーソル下シンボルのハイライトなどのキーマップ・機能を提供する。診断（エラー/警告）は、行末への常時インライン表示（virtual_text）やカーソル静止時の自動フロート表示は行わず、`<space>e`キー押下時にのみカーソル行の診断をフロート表示する（カーソルを動かすと自動的に閉じる）運用にしている（機能11のgitsigns差分プレビュー等と視覚的に競合しないようにするため。波線によるエラー箇所の下線表示(underline)は常時表示のまま）。また、`.java`ファイルで`preservim/vim-markdown`との競合により発生するエラー（Javadoc向けMarkdown連携機能起因）を避けるため、`g:java_ignore_markdown`を設定する。Java（jdtls）のみはこの共通ループには含まれず、機能4-2として個別にセットアップする。 | `lsp_settings.lua`, `lsp_settings.vim` |
| 4-2 | Java（jdtls）専用LSPセットアップ | `nvim-jdtls`のAPI（`require('jdtls').start_or_attach`）を用い、Javaファイルを開いた際に`ftplugin/java.lua`（Neovimの`filetype plugin on`により`.java`ファイルを開くと自動読み込みされる）でjdtlsを個別にセットアップする。プロジェクト（`root_dir`）ごとに`vim.fn.stdpath('cache')`配下の独立したワークスペースディレクトリ（`-data`）を割り当てるため、複数のJavaプロジェクトを行き来してもワークスペース状態が衝突しない。ルートマーカー（既定: `.git`, `mvnw`, `gradlew`, `pom.xml`, `build.gradle`）や`settings.java`へマージする追加設定（`extra_settings`）は、プロジェクトルートに置いた`.nvim.lua`から`vim.g.jdtls_project_overrides`を設定することでプロジェクトごとに上書きできる（機能1の`exrc`を参照）。オーバーライドが無い場合は既定値のみで動作する。キーマップ・nvim-cmp連携（`capabilities`）は機能4の共通`on_attach`/`capabilities`を`require('lsp_settings')`経由で再利用し、他言語と揃えている。 | `ftplugin/java.lua`, `lsp_settings.lua` |
| 5 | シンタックスハイライト | `nvim-treesitter`による構文ベースのハイライトと、True Color非対応ターミナルでも動作する`molokai`カラースキームを組み合わせて提供する。 | `treesitter_settings.lua`, `init.vim` |
| 6 | アウトライン表示 | `vista.vim`とctagsを用いて、ファイル内の見出しや定義一覧をサイドバー表示する（`<C-k>`でトグル）。Markdownファイルでは自動的に見出し一覧を表示する。 | `outline_settings.vim` |
| 7 | Markdownプレビュー | `selimacerbas/markdown-preview.nvim`（依存: `selimacerbas/live-server.nvim`）によりMarkdownのライブプレビューをブラウザで提供する（折り畳み機能は無効化）。mermaid図はブラウザ側で常に最新のmermaid.jsを使って描画され、クリックでのフルスクリーン表示・ズーム/パン・SVGエクスポートを標準搭載。加えて、プレビュー画面内に見出し一覧の折りたたみサイドバーを独自に追加しており、見出しクリックで該当箇所へスクロールジャンプできる（`custom_css`オプションの実装の隙を突いたJavaScript注入による自前実装。公式サポート外の方法である点に注意。詳細は`markdown_preview_toc.css`冒頭のコメントを参照）。Neovim側の見出しアウトライン(機能6, `<C-k>`)とは独立した別機能。 | `markdown_preview_settings.lua`, `markdown_preview_toc.css`, `markdown-preview-settings.vim`, `load_dein.vim` |
| 8 | HTMLプレビュー | `live-preview.nvim`によりHTMLファイル編集時のライブプレビューを提供する。 | `load_dein.vim`（プラグイン登録のみ） |
| 9 | 設定のデプロイ | 本リポジトリの設定ファイル群を、`rsync`を用いて実行環境の実際のNeovim設定ディレクトリ（例: `~/.config/nvim`）へ同期する。開発用ファイル（`docs`、`package.json`等）は同期対象から除外する。 | `deploy.sh` |
| 10 | TypeScript静的解析（ESLint）導入 | Neovim側のESLint（LSP）連携設定に加え、解析対象のTypeScriptプロジェクト側に必要な設定・導入手順をドキュメント化する。 | `.eslintrc.json`, `package.json`, `docs/typescript-linter-setup-guide.md` |
| 11 | Git差分表示 | `gitsigns.nvim`により、git管理下のバッファでVSCode風に変更行をsign column＋行背景色でハイライトする。ハンク単位でのインライン差分プレビュー切り替え（`<space>hp`）、前後ハンクへのジャンプ（`]c`/`[c`）、カーソル位置ハンクの変更前内容へのリセット（`<space>hr`）、表示全体のON/OFFトグル（`<space>gt`）のキーマップを提供する。git管理下でないバッファには自動的にアタッチしない。 | `gitsigns_settings.lua`, `load_dein.vim` |

## フォルダ構成
```
neovim-settings/
├── docs/                          # ドキュメント類
│   ├── typescript-linter-setup-guide.md   # TypeScript静的解析導入ガイド
│   └── 基本設計書.md               # 本ドキュメント
├── ftplugin/
│   └── java.lua                   # Java(jdtls)専用LSPセットアップ。filetype=javaで自動読み込み
├── node_modules/                  # npmパッケージの実体（.gitignore対象、ESLint関連の依存）
├── init.vim                       # Neovim設定のエントリポイント。基本設定・各設定ファイルの読み込みを行う
├── load_dein.vim                  # dein.vimによるプラグイン定義・管理
├── load_ime_control.vim           # IME自動切り替え設定
├── lsp_settings.lua                # LSPサーバー・補完（nvim-cmp）の設定。jdtls用にon_attach/capabilitiesもエクスポートする
├── lsp_settings.vim                # LSP関連のグローバル変数設定（Java向けMarkdown連携の無効化等）
├── gitsigns_settings.lua           # gitsigns.nvimのsetup()呼び出し・キーマップ定義
├── treesitter_settings.lua         # Treesitterによるシンタックスハイライト設定
├── outline_settings.vim            # Vista.vimによるアウトライン表示設定
├── markdown-preview-settings.vim   # Markdownプレビュー関連の補助設定（折り畳み無効化のみ）
├── markdown_preview_settings.lua   # selimacerbas/markdown-preview.nvimのsetup()呼び出し
├── markdown_preview_toc.css        # プレビュー内見出し一覧サイドバー(JS注入、custom_cssとして読み込む)
├── deploy.sh                       # 実行環境への設定デプロイスクリプト
├── package.json                    # Node.js依存関係定義（ESLint、TypeScript等）
├── package-lock.json               # npm依存関係のロックファイル
├── .eslintrc.json                  # ESLintのルール定義（サンプル/プロジェクト向け）
└── .gitignore
```

## 開発環境
本リポジトリはNeovimのエディタ設定そのものであるため、設定記述に使用する言語と、LSPによって解析支援の対象となる言語の2種類が存在する。

### 設定記述言語
- **Vim script（`.vim`）**: `init.vim`、`load_dein.vim`、`load_ime_control.vim`、`lsp_settings.vim`、`outline_settings.vim`、`markdown-preview-settings.vim`
- **Lua**: `lsp_settings.lua`、`treesitter_settings.lua`、`markdown_preview_settings.lua`、`gitsigns_settings.lua`（`init.vim`から`lua << EOF ... EOF`ブロック経由で読み込まれる）、`ftplugin/java.lua`（Neovimの`filetype`機構により`.java`ファイルを開いた際に自動読み込みされる）
- **CSS + JavaScript**: `markdown_preview_toc.css`（`custom_css`オプション経由でブラウザプレビューの`<head>`に注入される。中身はCSSとJavaScriptの両方を含む特殊なファイル）
- **Bash**: `deploy.sh`（設定ファイルのデプロイ処理）

### 補助ツール・パッケージ管理
- **npm / Node.js**: `package.json`、`package-lock.json`により、ESLint・TypeScript関連パッケージ（`eslint`、`typescript`、`@typescript-eslint/parser`、`@typescript-eslint/eslint-plugin`）を管理する。これはNeovim自体の動作用ではなく、TypeScript静的解析機能の検証・ドキュメント化のための依存関係である。
- **tree-sitter CLI / Cコンパイラ**: `nvim-treesitter`（`load_dein.vim`で`main`ブランチを明示的に指定）はパーサーのビルドを完全に外部の`tree-sitter` CLI本体とCコンパイラに委譲する設計であり、いずれも本リポジトリの管理対象外の前提ツールとして利用環境に別途インストールしておく必要がある（未導入だと`treesitter_settings.lua`のFileTypeautocmdによる自動インストールが`ENOENT ... 'tree-sitter'`のようなエラーで失敗し続ける）。macOSではHomebrewの`tree-sitter-cli`パッケージ（`nvim-treesitter`の要件である0.26.1以上が必要。2026年8月時点のHomebrew配布バージョン0.26.13で動作確認済み）とXcode Command Line Tools（`clang`）の組み合わせで動作を確認済み。Windowsでの導入方法は`docs/Windows11導入手順.md`の3.2節を参照。

### LSPによる解析支援対象言語（`lsp_settings.lua`で設定）
Python（ruff, pyright）、Rust（rust_analyzer）、TypeScript/JavaScript（ts_ls, eslint）、C/C++（clangd）、C#（csharp_ls）、Vim script（vimls）、HTML（html）、CSS（cssls）、JSON（jsonls）、Lua（lua_ls）、PowerShell（powershell_es）は`lsp_settings.lua`の共通`servers`ループでセットアップされる。Java（jdtls）のみは`ftplugin/java.lua`で個別にセットアップされる（機能4-2を参照。Homebrew等で`jdtls`コマンドを別途導入する必要がある点は他と同様）。

### プラグイン管理
- **dein.vim**: Neovimプラグイン全般の管理に使用（`load_dein.vim`）

### 対象実行環境
- Windows / macOS / Linuxの3環境に対応し、`init.vim`および`load_ime_control.vim`内でOS判定による分岐処理を行う。

## その他
- コミット履歴によれば、`nvim-treesitter`によるシンタックスハイライトはWindows/macOSでそれぞれ異なる不具合が生じたため一時的に削除された経緯があり、現在はTrue Color非対応ターミナルでも動作する`molokai`カラースキームと組み合わせて再導入されている。
- 検索時のハイライトはデフォルトで無効化されており、`<C-h>`で都度トグルする運用になっている。
- `deploy.sh`は`rsync --delete --delete-excluded`を使用するため、実行環境の設定ディレクトリ内でリポジトリに存在しないファイルは削除される点に注意が必要である。また`.git`、`node_modules`、`docs`、`.gitignore`、`package.json`、`package-lock.json`、`deploy.sh`、`.claude`は同期対象から除外され、`--delete-excluded`によりこれらは実行環境の設定ディレクトリに既に存在していても削除される（`.claude`はこのリポジトリ自体のClaude Code設定であり、Neovim設定ディレクトリ側には不要なため）。
- Java（jdtls）は他の言語のようにLSPサーバーを一括セットアップする`lsp_settings.lua`の共通ループ（`servers`テーブル）には含めず、`ftplugin/java.lua`で`nvim-jdtls`自身のAPI（`require('jdtls').start_or_attach`）を使い個別にセットアップする。理由は、jdtlsは他のLSPサーバーと異なりプロジェクト（`root_dir`）ごとに独立したワークスペース状態ディレクトリ（`-data`）を必要とするなど、単純なデフォルト設定の共有では表現しづらい要件があるため。`jdtls`コマンド自体は他の言語同様に本リポジトリの管理対象外であり、利用環境に別途インストールしておく必要がある（macOSでは`brew install jdtls`）。
  - **ワークスペースディレクトリの分離**: `root_dir`のパスをサニタイズした文字列を使い、`vim.fn.stdpath('cache') .. '/jdtls-workspace/' .. <サニタイズ済みroot_dir名>`という専用ディレクトリを`-data`として渡す。これにより、異なるJavaプロジェクトを（同一/別セッション問わず）開いてもjdtlsのワークスペース状態が衝突しない。
  - **プロジェクトごとの上書き（`.nvim.lua`）**: ルートマーカー（既定: `.git`, `mvnw`, `gradlew`, `pom.xml`, `build.gradle`）や、jdtlsの`settings.java`にマージされる追加設定（`extra_settings`）は、`ftplugin/java.lua`内で「デフォルト + `vim.g.jdtls_project_overrides`による上書き」という構造になっている。`vim.g.jdtls_project_overrides`が未設定の場合はデフォルトのみで問題なく動作する。個々のJavaプロジェクト側でこれを上書きしたい場合は、そのプロジェクトのルートディレクトリに`.nvim.lua`を置き、以下のように記述する（機能1の`vim.o.exrc = true`により、`secure`が制限されたサンドボックス内で自動的に読み込まれる）。
    ```lua
    -- <Javaプロジェクトルート>/.nvim.lua
    vim.g.jdtls_project_overrides = {
      root_markers = { '.git', 'pom.xml' },
      extra_settings = {
        -- settings.java にディープマージされる
      },
    }
    ```
    `.nvim.lua`はNeovimの起動ディレクトリ（カレントディレクトリ）に依存したローカル・per-checkoutな設定であり、通常は各Javaプロジェクト側の`.gitignore`に加えてコミットしない運用を想定している（本リポジトリ自体の管理対象ではなく、あくまで各Javaプロジェクト側に置く前提のファイルである点に注意）。
  - `on_attach`（キーマップ）・`capabilities`（nvim-cmp連携）は、`lsp_settings.lua`が`require('lsp_settings')`の戻り値として公開しているものを`ftplugin/java.lua`から再利用しており、他言語のLSPと挙動を揃えている。
- `.java`ファイルを開く際、`preservim/vim-markdown`プラグイン同梱の独自`syntax/markdown.vim`が原因で、`syntax/java.vim`のJavadoc向けMarkdown連携機能（JEP 467、`///`コメント）が`E28: No such highlight group name`エラーを出す不具合があるため、`lsp_settings.vim`で`g:java_ignore_markdown = 1`を設定し、この連携機能自体を無効化している（対処法は`:h ft-java-plugin`に準拠）。
- `markdown_preview_toc.css`（プレビュー内見出し一覧サイドバー）は、`selimacerbas/markdown-preview.nvim`の`custom_css`オプションの実装（指定ファイルの中身を無加工のまま`<style>`として`<head>`直前に挿入するだけでエスケープ処理が無い）を利用し、CSSブロックの途中で意図的にstyle終了・script開始のタグを書いてJavaScriptを注入する、公式サポート外の方法で実装されている。これは唯一の公式な拡張ポイントである`custom_css`しか存在せず、`[[toc]]`記法や見出し一覧表示に相当する機能が本プラグインに存在しないため採用した回避策である（比較検討の経緯・代替案は本タスクの調査記録を参照）。将来`selimacerbas/markdown-preview.nvim`側で`custom_css`の挿入処理にエスケープが入る等の変更があった場合、このサイドバー機能だけが静かに動作しなくなる可能性がある（プレビュー本体・mermaid描画等の他機能には影響しない設計）。プラグインを更新した際は、プレビューを開いて目次ボタンが表示されるか目視確認することが望ましい。
- Git差分表示（`gitsigns.nvim`、機能11）は、既存プラグイン（`vim-signify`、`mini.diff`等）と比較検討した上で、ハンク単位のインラインプレビュー・リセット等をすべて公式APIのみで実現でき依存プラグインも不要な`gitsigns.nvim`を採用した。
  - **設定**: `signcolumn = true`（既定）に加え`linehl = true`を明示指定し、sign columnだけでなく変更行全体の背景色も変更する（VSCode風の表示にするため）。
  - **キーマップの衝突確認**: 導入前に`lsp_settings.lua`（`on_attach`内の全キーマップ）・`init.vim`・`outline_settings.vim`の既存キーマップを洗い出した上で、未使用のキーのみを割り当てている。`]c`/`[c`（ハンク間ジャンプ）は`lsp_settings.lua`の`[d`/`]d`（診断のprev/next）と同じ「ブラケット+prev/next」の慣習に合わせたもので、Vimの差分モード(`:h 'diff'`)中は組み込みの`]c`/`[c`へフォールバックする（`gitsigns.nvim`公式サンプルと同じ実装）。`<space>hp`（`preview_hunk_inline()`、インライン差分プレビューのトグル）・`<space>hr`（`reset_hunk()`、カーソル位置ハンクを変更前の内容に戻す）・`<space>gt`（`toggle_signs()`/`toggle_linehl()`を同期させて呼び出す自前の薄いラッパー関数で、表示全体のON/OFFを切り替える）は既存の`<space>`系キーマップと重複しない。なお`gitsigns.nvim`公式READMEが例示する`<leader>h...`系のキーマップは、本リポジトリで`mapleader`を設定しておらず既存キーマップも軒並み`<space>`直書きであるため採用せず、既存の命名慣習に合わせて`<space>`系に置き換えている。
  - **他機能との関係**: `gitsigns.nvim`はfiletypeに依存せずgit管理下のバッファへ汎用的にアタッチする仕組みであるため、jdtls（機能4-2）やMarkdownプレビュー（機能7）とは名前空間・キーマップ・autocmdグループのいずれも重複しない。また`vim.diagnostic.config()`で`signs = false`としているため、sign columnはgitsigns用に空いており競合しない。
- **LSP診断表示のトリガーキー化**: 当初はLSP診断メッセージを`virtual_text`（行末への常時インライン表示）に加え、`CursorHold`（カーソル静止）で自動的にフロート表示していたが、gitsignsの差分プレビュー（`<space>hp`、`preview_hunk_inline()`）を確認しようとカーソルを止めた瞬間に、この自動フロートが割り込んで表示を覆ってしまう不具合が報告された。対応として、`vim.diagnostic.config()`の`virtual_text`を`false`に変更し、`on_attach`内の`CursorHold`自動フロートautocmdを削除。診断確認は既存の`<space>e`（`vim.diagnostic.open_float()`）キー押下時にのみ行う運用に変更した。`vim.lsp.util.open_floating_preview()`の既定`close_events = {CursorMoved, CursorMovedI, InsertCharPre}`によりカーソルを動かすと自動的に閉じるため、gitsignsの`<space>hp`と同様の「押した時だけ確認できる」UXになっている（新規キーマップの追加は不要）。`<space>q`（`setloclist()`、診断一覧をlocation listへ）は本件と無関係のため変更していない。`underline`（波線）は背景/前景色を変更せず画面を覆うこともないためgitsignsの表示と競合せず、既定値のまま常時表示を維持している。`signs`は元々`false`のため変更なし。
